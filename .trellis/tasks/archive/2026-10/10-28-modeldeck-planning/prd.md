# DSH ModelDeck（模型卡组）需求

## 目标

规划 DSH 插件 **DSH ModelDeck（模型卡组）**，插件 ID 为 `dsh-modeldeck`。它让用户在会话中快速应用已保存的「提供商 + 模型 + 推理等级」组合，并按项目保存固定配置与最近历史。

本任务处于需求规划阶段，**用户已于 2026-10-28 确认本规划为定稿**。用户此前选择**交付方式 B：仅交付插件**、决定**放宽严格会话隔离**，并确认了规划默认值 D1-D11。定稿仅表示需求规划完成，不代表批准开始实现。

## 背景与已确认事实

- 用户提出六组功能：项目隔离、固定配置、最近历史、钉住、快捷切换、兼容与异常处理。
- 决定性验收重点为：项目数据互不干扰、历史正确去重与排序、钉住状态持久保存、后续请求实际使用所选配置。
- 工作区目前只有 Trellis 脚手架，未发现已有的插件应用源码、包清单或 README。
- 已核实的安装版本为 DSH **0.2.1-rc.3**，nightly 构建提交 `be72761ee1a6736ebcdf4f3739363b083ae53c98`；更早版本的兼容性未得到证实。见[安装接口调研](research/installed-dsh-contracts.md#L16)。
- 通过 DSH 自带入口成功切换模型是可观察的，重复应用同一组合也会产生事件；只观察界面状态变化会漏掉重复应用。见[成功切换事件证据](research/installed-dsh-contracts.md#L39)。
- **R5 / AC-07 的兼容风险**：当前标准切换接口在应用会话选择的同时，也会更新共享的配置文件默认值，可能影响未来会话及尚未使用过的会话。见[范围冲突说明](research/installed-dsh-contracts.md#L102)。
- 后续可行性调研确认：在此构建上，不存在受支持的纯插件隔离机制；详见下方交付范围一节。

## 已确认交付范围：方案 B

- `dsh-modeldeck` 仅以插件形式交付。不修改 DSH 应用本体、不修改其安装文件、也不配套交付宿主（Host）接口改动。
- 可行性调研发现：**在受支持的纯插件接口下，无法实现严格的“仅当前会话”应用**。共享切换接口没有隔离开关，并且会无条件保存全进程共享的默认值。见[插件隔离可行性](research/plugin-isolation-feasibility.md#L8)。
- 存在一个会话级内部机制，但它并非导出或文档化的契约，且绕过了校验与错误映射；不允许把它作为静默替代方案。见[内部调用风险](research/plugin-isolation-feasibility.md#L37)。
- 共享默认值不按项目隔离，因此默认值变化也可能影响其他项目中的全新会话、尚未使用过的会话，以及未来新建的会话。见[共享默认值范围](research/plugin-isolation-feasibility.md#L75)。
- **已定决策：放宽严格隔离。** 虽然受支持的纯插件接口无法实现严格“仅当前会话”，但用户选择接受该接口的共享默认值副作用，以保证切换功能可以交付。ModelDeck 必须**明确披露**该副作用，不得隐瞒。

## 确认的需求

### R1. 按项目隔离的持久化

- 固定配置、最近历史、钉住状态和固定配置排序均归属于项目。
- 切换项目时加载该项目自己的数据，不共享、不覆盖其他项目的数据。
- 重新打开项目以及重启 DSH 后，保存的数据仍然保留。
- 项目级列表可在该项目的多个会话间共用，而应用某次选择只作用于当前会话（见 R5）。

### R2. 固定配置管理

- 每个配置包含显示名称、提供商、模型，以及模型支持时的推理等级。
- 用户可手动新增、编辑、排序和移除固定配置。
- **新增固定配置时，从 DSH 现有可用模型目录中选择**提供商、模型及受支持的推理等级，而不是手工输入 ID；选择范围与 R6 的可用性规则一致。
- 固定区条目由**手动新增**与**钉住历史**两类来源组成；由历史钉住上来的固定项与手动新增的固定项**能力一致**，均可改名、排序、移除。
- 显示名称不参与配置组合的身份判断。
- 固定配置的排序独立于最近历史的排序，单独持久化。

### R3. 最近历史

- 仅当某组合已成功应用到会话后，才自动记录该「提供商 + 模型 + 推理等级」组合。
- 按完整组合去重，而不是按显示名称。
- 再次使用某组合时，更新其最后成功使用时间，并置顶到最近历史最前。
- 最近历史按最近成功使用时间倒序排列。
- 最近历史设有限额；超出时淘汰最旧的可淘汰条目。
- 被拒绝或失败的应用不产生成功历史，也不改变既有历史的顺序。
- 具体限额与观察来源按下方规划默认值 D1、D2 执行。

### R4. 钉住历史

- 历史条目可一键钉住，钉住后进入固定区。
- 已钉住的组合不受最近历史数量上限限制。
- 取消钉住后，该组合回到正常的历史处理规则。
- 同一组合不得同时出现在固定区和历史区。
- 钉住状态在切换项目和重启 DSH 后仍然保留。

### R5. 快捷切换与当前状态

- 在会话界面提供入口，展示固定配置与最近历史。
- 点击有效条目时，使用**受支持的 DSH 接口**，将完整配置应用到当前项目的当前会话，供后续请求使用。
- 应用会立即对目标会话生效。由于受支持的接口同时保存共享默认值，ModelDeck 必须在界面中**明确说明**：其他项目中未做选择的或新建的会话，之后可能继承该默认值。
- 实现不得依赖未文档化的内部接口（例如未导出的会话级选择方法）。
- 展示当前会话的实际配置，并高亮与之匹配的条目。
- 当没有任何条目匹配当前配置时，显示「自定义」。
- 展示结果与应用结果必须与后续请求实际使用的有效会话配置一致。
- 用户切换项目或会话后，异步操作不得把选择或历史写入新的、无关的上下文。

### R6. 兼容与异常处理

- 仅使用 DSH 已配置的提供商与模型，以及这些模型支持的推理等级。
- 模型不支持推理等级时，隐藏推理等级选择控件。
- 判断配置组合时，将「不支持推理」视为「不适用」，不得虚构可选择的值。
- 当已保存的配置不可用或应用失败时，说明原因、保留原有有效配置，且不写入成功历史。
- 不得擅自用其他提供商、模型或推理等级替代不可用的已保存选择。
- 应用成功的判定标准是 DSH 确认会话配置已更新；此后某次生成请求失败，不会反推为配置应用失败。

## 验收标准

| 编号 | 场景 | 可观察结果 | 对应需求 |
| --- | --- | --- | --- |
| AC-01 | 在项目 A、B 中分别维护不同数据，并在两者之间来回切换。 | 各自固定配置、历史、钉住状态与排序正确恢复，互不污染。 | R1 |
| AC-02 | 在 A、B 中保存数据后重启 DSH，再分别打开。 | 两个项目的数据各自独立保留。 | R1、R4 |
| AC-03 | 依次成功应用 X、Y、X，且三者初始均未钉住。 | 最近历史为 X、Y，且 X 只出现一次。 | R3 |
| AC-04 | 应用足够多不同组合以超过选定上限。 | 淘汰最旧的非固定条目，固定项保留。 | R3、R4 |
| AC-05 | 钉住历史中的 X，切换项目并重启 DSH。 | X 仍固定在其所属项目，且不在历史区重复展示。 | R1、R4 |
| AC-06 | 取消钉住某已保存组合。 | 按既定历史归位与容量规则处理，且不同时出现在两个区域。 | R3、R4 |
| AC-07 | 在会话 A 中应用配置，同时存在一个已有明确选择或已发过请求的会话 B。 | A 的后续请求使用所选配置；B 保持自身配置。界面说明共享默认值已变化，可能影响全新/未使用会话及未来会话。 | R5 |
| AC-08 | 将当前配置与列表条目比对。 | 匹配项高亮；无匹配时显示「自定义」，同时保留实际配置的展示。 | R5 |
| AC-09 | 应用不可用配置，或模拟应用失败。 | 明确显示原因，原有有效配置与历史内容和顺序保持不变。 | R3、R6 |
| AC-10 | 应用过程中切换项目或会话。 | 不把配置或历史结果归到新选择的无关联上下文。 | R1、R5 |
| AC-11 | 通过受支持的 DSH 入口改变有效会话配置。 | 插件对当前状态的展示与高亮反映实际配置；历史捕获按确认的观察范围检查。 | R3、R5 |
| AC-12 | 应用某条目后提交一次请求。 | 请求链路证据确认提供商、模型及适用的推理等级与所选条目一致；仅凭界面高亮不够。 | R5、R6 |
| AC-13 | 新增、编辑、排序、移除固定配置后重新打开项目。 | 已确认的字段与排序被保留，移除项遵循既定移除语义。 | R1、R2 |
| AC-14 | 选择支持与不支持推理等级的模型。 | 仅提供受支持选项；不支持的推理控件被隐藏，无效的已保存选择会被说明。 | R6 |
| AC-15 | 应用一次切换并检查界面与集成。 | 切换只使用受支持的 DSH 接口，界面已披露共享默认值副作用，且未调用未文档化的内部会话方法。 | 交付方案 B、R5、R6 |
| AC-16 | 新增固定项时，从现有模型目录中选择提供商、模型和推理等级。 | 只能选择 DSH 已配置且当前可用的模型与受支持的推理等级；不支持推理时隐藏该选项；保存后的固定项字段与所选一致。 | R2、R6 |

## 首版范围外

跨项目共享、云同步、导入导出、按任务自动选择模型、提供商凭据管理，以及在 DSH 现有配置之外新建提供商/模型定义，均不在首版范围内（以最终范围审阅为准）。

## 规划默认值（已确认，2026-10-28）

用户已要求按建议继续推进并确认。以下作为首版工作默认值，均已确认。

- D1：最近历史限额为每个项目 20 个组合；首版不提供限额设置界面。
- D2：插件运行期间，观察当前项目内所有成功的相关会话配置变更，包含通过 DSH 自带控件所做的切换，而不仅是 ModelDeck 发起的切换。
- D3：每个完整组合只允许一个固定项；新增或编辑发生冲突时给出提示并拒绝，不产生重复卡片。
- D4：取消钉住时保留最后成功使用时间，并按该时间回到历史；取消钉住本身不算一次使用，因此按正常容量规则可能被立即淘汰。
- D5：移除固定项只删除固定项，不删除其历史记录；彻底删除历史需单独显式操作。从未成功使用过的手动固定项被移除时直接删除，不再出现在历史区。
- D6：新增、编辑、排序、移除、钉住等列表管理操作，一律不隐式应用到会话。
- D7：不可用的已保存条目仍然显示，并给出说明，便于用户编辑或移除。
- D8：入口先展示精简的当前配置摘要；展开后显示当前配置、固定配置、最近历史与管理操作。
- D9：持久化失败必须明确提示，绝不能显示为已成功保存。
- D10：由历史钉住上来的固定项与手动新增的固定项能力一致，均可改名、排序、移除。
- D11：从现有模型目录新增固定项时，默认名称使用「提供商 / 模型（推理等级）」自动生成，用户可在保存前改名。

## 仍需核实的技术证据

- 核实稳定的项目标识、生命周期，以及项目上下文的变更观察。
- 核实项目级的持久化存储、并发处理与写入失败的上报方式。
- 按放宽后的隔离决策及其披露的共享默认值副作用来验证 AC-07，而非严格会话隔离。
- 补全会话入口的交互插槽契约，并确定最低兼容的 DSH 版本。
- 确定并验证断连或崩溃后的历史补录（回放）行为；仅靠实时事件观察不足以证明可回放或可持久写入。
- 验证适配器自定义的推理等级 ID 与规范化后的成功选择；模型目录、整组合更新的确认与后续请求路由已有安装源码证据，但尚未做真实运行时验证。

若后续批准实现，技术架构与执行清单将写入 `design.md` / `implement.md`。本任务当前为**已确认的需求规划定稿**，尚未进入实现。本规划任务不授权任何产品实现或对已安装 DSH 的改动。
